02 / How I work

Principles behind the work.

  1. Measure the thing that matters

    Fingerboard Coach doesn't say "a bit sharp". It reports +12¢ and how far to move the finger. Vague feedback doesn't change anything, for people or for systems.

  2. Design for the person on the other end

    Players, people learning a dance, the engineer reviewing someone else's diff. Each tool here starts from how its user actually works.

  3. Scale judgment, not just output

    Generated code arrives faster than anyone can review it. pr-review spends effort on the reviewer's attention, which is the real bottleneck.

  4. Leave it runnable

    One command to start, thresholds kept in one config file, and decisions written down where the next engineer will look.
